# Шпаргалка для защиты лабы: Очередь с поддержкой GetMin и GetMax (Lazy Deletion)

## 1. Связь с исходной задачей
Планировщику нужна структура данных (очередь), которая поддерживает три команды:
1. `Insert x` — добавить приоритет \(x\).
2. `GetMin` — извлечь и вывести минимальный приоритет.
3. `GetMax` — извлечь и вывести максимальный приоритет.

**Проблема:** Стандартная куча (priority_queue в C++) умеет быстро делать только что-то одно (либо Min, либо Max).
**Решение:** Использовать **две кучи** (Min-Heap и Max-Heap) одновременно и применить технику **"ленивого удаления" (Lazy Deletion)**.

---

## 2. Главная фишка кода: Ленивое удаление (Lazy Deletion)

Если мы просто добавим элементы в обе кучи, при извлечении из одной кучи, элемент останется во второй, что приведет к дубликатам. 
Чтобы этого избежать, мы не ищем и не удаляем элемент из второй кучи сразу (это долго, \(O(N)\)). Вместо этого мы **помечаем элемент как удаленный**.

В коде это реализовано через структуру `Item` и массив `removed`.
* Каждому вставленному элементу дается уникальный `index` (порядковый номер команды).
* `std::vector<bool> removed(N + 1, false);` — массив, где мы храним `true`, если элемент с таким индексом уже был извлечен из одной из куч.

---

## 3. Разбор кода по шагам

### Структура элемента
```cpp
struct Item{
    long long value;
    int index;
};
```
**Зачем это нужно:** Нам нужно знать не только значение приоритета (`value`), но и уникальный номер (`index`), чтобы понимать, был ли этот элемент уже "удален" через другую кучу.

### Пространства имен `MaxHeap` и `MinHeap`
Там реализованы стандартные функции `SiftUp` (просеивание вверх при вставке) и `SiftDown` (просеивание вниз при удалении корня).
Разница лишь в знаках сравнения (`>` для Max и `<` для Min).

### Функция `Insert` (Вставка)
```cpp
void Insert(std::vector<Item> &list, long long insertion, int index, bool Max){
    list.push_back({insertion, index});
    if (Max){
        MaxHeap::SiftUp(list, list.size() - 1);
    } else {
        MinHeap::SiftUp(list, list.size() - 1);
    }
}
```
При команде `Insert` мы добавляем элемент **в обе кучи**, передавая им одинаковый `index`.

### Функция `Delete` (Удаление корня)
```cpp
void Delete(std::vector<Item> &list, bool Max){
    std::swap(list[0], list[list.size() - 1]);
    list.erase(list.begin() + list.size() - 1);
    if (Max){
        MaxHeap::SiftDown(list, 0);
    } else {
        MinHeap::SiftDown(list, 0);
    }
}
```
Удаляет верхушку (корень) из конкретной кучи: меняет местами с последним элементом, удаляет последний из вектора и "просеивает" новый корень вниз.

### Обработка команд (Main)
```cpp
if (currentOperation[0] == 'I') { ... }
else if (currentOperation[4] == 'a') { // GetMax (буква 'a' в слове Max)
    while (removed[maxHeap[0].index]){
        Delete(maxHeap, true);
    }
    std::cout << maxHeap[0].value << '\n';
    removed[maxHeap[0].index] = true;
    Delete(maxHeap, true);
}
```
**Как работает извлечение (на примере GetMax):**
1. Смотрим на верхушку `maxHeap`.
2. Запускаем цикл `while`. Если индекс верхушки помечен как `removed` (т.е. этот элемент уже извлекли через `GetMin`), мы просто выкидываем его из `maxHeap` с помощью `Delete`. Делаем так, пока наверху не окажется "живой" элемент.
3. Выводим значение верхушки.
4. Помечаем индекс этой верхушки как `removed = true` (чтобы в будущем его пропустила `minHeap`).
5. Удаляем этот элемент из текущей кучи.

*(Для `GetMin` логика абсолютно такая же, только с `minHeap`).*

## 4. Сложность алгоритма (Вопросы на защите)
* **Время работы:** \(O(q \log q)\), где \(q\) — количество команд.
  * Вставка (`Insert`) — \(O(\log q)\) (так как размер кучи может достигать \(q\)).
  * Извлечение (`GetMin`/`GetMax`) — в худшем случае цикл `while` может удалить много элементов за один вызов. Но каждый элемент удаляется ровно один раз (один раз из `minHeap` и один раз из `maxHeap`). Поэтому общее время работы всех циклов `while` за всю программу — \(O(q \log q)\). Это называется **амортизированная сложность**.
* **Память:** \(O(q)\). Мы храним до \(q\) элементов в двух кучах (итого \(2q\)) и массив `removed` размера \(q\).

## 5. Возможные вопросы преподавателя и ответы на них

**Вопрос:** Зачем ты реализовывал ручной парсинг строки (извлечение цифр из `currentOperation`), почему не использовал `std::stringstream` или просто `std::cin >> string >> x`?
**Ответ:** Во-первых, команды `GetMin` и `GetMax` не имеют аргументов. Если использовать `cin >> string >> x`, программа зависнет в ожидании числа на командах извлечения. Во-вторых, ручной парсинг (`currentOperation[j] >= '0' && ...`) работает быстрее и позволяет легко обрабатывать отрицательные числа (флаг `isNegative`), не подключая тяжелые библиотеки.

**Вопрос:** Почему ты не удаляешь элемент из второй кучи сразу, когда извлекли из первой?
**Ответ:** Поиск произвольного элемента в куче (не корня) занимает \(O(N)\). Если мы будем делать это при каждом извлечении, общая сложность программы вырастет до \(O(q^2)\), что при \(q = 100 000\) приведет к Time Limit Exceeded (TLE). Ленивое удаление позволяет обойтись \(O(q \log q)\).

**Вопрос:** Как ты определяешь, какую команду ввел пользователь? (`currentOperation[4]`)
**Ответ:** Строка `GetMax` имеет длину 6, `GetMin` — тоже 6. Символ с индексом 4 (пятый по счету) — это `M` в `GetMax` (не подходит, код проверяет `a`). На самом деле, в слове `GetMax` символ `[4]` — это `a`, а в `GetMin` — `i`. Код проверяет `currentOperation[4] == 'a'` для `GetMax` и `== 'i'` для `GetMin`. Это надежный и быстрый способ отличить их.

**Вопрос:** Почему в структуре `Item` тип `value` — `long long`, а `index` — `int`?
**Ответ:** По условию значения \(x\) могут достигать \(2 \cdot 10^9\), что близко к пределу 32-битного знакового `int` (2.14 * 10^9). Чтобы избежать переполнения при возможных операциях, надежнее использовать `long long`. А количество операций \(q \le 100 000\), поэтому для `index` с головой хватит обычного `int`.

**Вопрос:** Что будет, если массив `removed` выйдет за границы?
**Ответ:** Этого не произойдет. Мы инициализируем `insertsCount` единицей и инкрементируем только при команде `Insert`. Количество вставок не может превысить общее количество команд \(N\). Размер массива `removed` задан как `N + 1`, поэтому индексы будут от 1 до `N`, что безопасно.

# Шпаргалка для защиты лабы: Пирамидальная сортировка (Heap Sort)

## 1. Связь с исходной задачей
По сюжету лабы планировщик `NIGHTBUILD` после аварии сбросил очередь процессов в неупорядоченное состояние. Нам нужно восстановить порядок, выведя приоритеты в порядке **неубывания** (от меньшего к большему).
В условии строго сказано: **необходимо использовать пирамидальную сортировку** (Heap Sort).

Пирамидальная сортировка работает за время \(O(N \log N)\) и является сортировкой на месте (не требует дополнительных массивов, кроме самого исходного).

---

## 2. Разбор кода по шагам

### Функция `SiftDown` (Просеивание вниз)
Это сердце алгоритма. Она восстанавливает свойства кучи, если они были нарушены.
```cpp
void SiftDown(std::vector<int> &list, int i, int size){
    while (2 * i + 1 < size){
        int left = 2 * i + 1;
        int right = 2 * i + 2;
        int j = left;

        if ((right < size) && ((list[right] > list[left]))){
            j = right;
        }

        if (list[i] >= list[j]){
            break;
        }

        std::swap(list[i], list[j]);
        i = j;
    }
}
```
**Как это работает:**
1. Мы находимся в узле `i`. Проверяем, есть ли у него потомки (`2 * i + 1 < size`).
2. Находим **наибольшего** из двух потомков (сравниваем `left` и `right`, записываем индекс в `j`).
3. Если текущий родитель `list[i]` уже больше или равен наибольшему потомку `list[j]`, то всё хорошо, кучу восстанавливать не нужно — выходим из цикла (`break`).
4. Иначе меняем родителя и потомка местами (`swap`) и спускаемся дальше вниз по дереву (`i = j`), чтобы проверить следую уровни.
*Здесь строится **Max-Heap** (куча, где родитель всегда больше своих детей).*

### Функция `BuildHeap` (Построение кучи)
```cpp
void BuildHeap(std::vector<int> &list){
    for (int i = list.size() / 2; i > 0; i--){
        SiftDown(list, i - 1, list.size());
    }
}
```
**Как это работает:**
Мы проходим по всем **нелистовым** узлам (начиная с `size / 2 - 1` и до нуля) и применяем к ним `SiftDown`.
* **Почему с середины?** В бинарном дереве, представленном массивом, вторая половина элементов (`size/2` до `size-1`) — это листья. У них нет детей, поэтому они уже являются корректными кучами (размером 1). Нам нужно просеять только "родителей".
* Сложность этой функции — **\(O(N)\)**, что быстрее, чем добавлять элементы по одному за \(O(N \log N)\).

### Функция `delete_max` (Извлечение максимума)
```cpp
void delete_max(std::vector<int> &list, int size){
    std::swap(list[0], list[size - 1]);
    SiftDown(list, 0, size - 1);
}
```
**Как это работает:**
В Max-Heap самый большой элемент всегда лежит в корне (индекс 0). Чтобы отсортировать массив по возрастанию, мы:
1. Меняем местами корень (максимум) с самым последним элементом текущей неотсортированной части.
2. Уменьшаем размер кучи на 1 (`size - 1`), так как максимум уже стоит на своем месте в конце.
3. Вызываем `SiftDown` для нового корня, чтобы восстановить кучу среди оставшихся элементов.

### Функция `HeapSort` (Сама сортировка)
```cpp
void HeapSort(std::vector<int> &list){
    BuildHeap(list);
    for (int size = list.size(); size > 1; size--){
        delete_max(list, size);
    }
}
```
**Как это работает:**
1. Сначала строим кучу (`BuildHeap`).
2. Затем в цикле от конца массива к началу "выкидываем" максимумы в конец (`delete_max`).
3. Когда цикл завершится, весь массив будет отсортирован по возрастанию.

## 3. Сложность алгоритма (Вопросы на защите)
* **Время работы (Time Complexity):** \(O(N \log N)\). Построение кучи занимает \(O(N)\). Затем мы \(N-1\) раз вызываем `delete_max`, каждый раз просеивая дерево за \(O(\log N)\).
* **Память (Space Complexity):** \(O(N)\) для хранения массива. Дополнительная память (in-place) — \(O(1)\), так как мы сортируем прямо в исходном массиве, используя только `swap`.
* **Почему `int` в этот раз, а не `long long`?** В условии \(|a_i| \le 10^9\). Максимальное значение 32-битного знакового `int` — \(\approx 2.14 \cdot 10^9\). Поэтому \(10^9\) отлично помещается в `int`, переполнения не будет.

## 4. Возможные вопросы преподавателя

**Вопрос:** Почему для сортировки по возрастанию ты строишь кучу на **максимум** (Max-Heap), а не на минимум?
**Ответ:** Потому что в Max-Heap наверху находится самый большой элемент. Мы меняем его с последним элементом массива. Таким образом, самый большой элемент встает в самый конец (где он и должен быть при сортировке по возрастанию). Затем мы отрезаем этот конец и продолжаем работать с оставшейся частью.

**Вопрос:** Зачем в `delete_max` передается параметр `size`?
**Ответ:** При сортировке куча "сжимается". Элементы, которые мы уже переставили в конец массива, больше не являются частью кучи. Параметр `size` ограничивает работу `SiftDown`, чтобы он не трогал уже отсортированную часть массива.

**Вопрос:** Почему в `BuildHeap` цикл идет от `list.size() / 2` до 1?
**Ответ:** В древовидном представлении массива индексы от `N/2` до `N-1` соответствуют листьям дерева. У листьев нет детей, поэтому они по умолчанию удовлетворяют свойствам кучи. Нет смысла вызывать для них `SiftDown`. Мы начинаем с последнего узла, у которого есть дети (индекс `N/2 - 1`).

**Вопрос:** Чем `SiftDown` (просеивание вниз) отличается от `SiftUp` (просеивание вверх)?
**Ответ:** `SiftUp` используется при добавлении элемента в кучу (он всплывает наверх, сравнивая себя с родителем). `SiftDown` используется, когда элемент в корне нарушает структуру (он тонет вниз, сравнивая себя с наибольшим из детей). В `HeapSort` используется `SiftDown`, так как мы всегда работаем с корнем.

**Вопрос:** Устойчива ли эта сортировка (Stable sort)?
**Ответ:** Нет. Пирамидальная сортировка не является устойчивой. При перестановках элементов (особенно при обмене корня с последним элементом) равные элементы могут поменять свой относительный порядок. Если бы в задаче требовалась устойчивость, пришлось бы использовать, например, сортировку слиянием или хранить пары (значение, исходный индекс).

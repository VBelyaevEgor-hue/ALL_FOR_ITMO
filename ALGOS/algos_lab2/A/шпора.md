# Шпаргалка для защиты лабы: Проверка инварианта пирамиды (Min-Heap)

## 1. Связь с исходной задачей
В условии сказано, что "сердце планировщика" — это приоритетная очередь, реализованная в виде **неубывающей пирамиды** (min-heap). 
Инвариант такой пирамиды гласит: **значение в любом родительском узле должно быть меньше или равно значениям его дочерних узлов**.

В задаче индексация элементов начинается с \(1\) (от \(1\) до \(n\)):
* Левый ребенок: \(2i\)
* Правый ребенок: \(2i + 1\)
* Условие: \(a_i \le a_{2i}\) и \(a_i \le a_{2i+1}\)

Твоя программа должна проверить, соблюдается ли это правило для всех элементов. Если да — планировщик стабилен (выводим `YES`), если нет — требуется ручная переконфигурация (выводим `NO`).

## 2. Разбор кода по шагам

```cpp
int N;
std::cin >> N;
std::vector <long long> list(N);
for (int i = 0; i < N; i++){
    std::cin >> list[i];
}
```
**Что происходит:** Считываем количество элементов \(N\), создаем вектор (динамический массив) `list` размера \(N\) и заполняем его значениями.
* **Почему `long long`?** По условию \(|a_i| \le 2 \cdot 10^9\). Хотя это влезает в обычный 32-битный `int` (максимум около \(2.14 \cdot 10^9\)), использование `long long` — это хорошая практика, чтобы избежать любых потенциальных переполнений при сравнении или будущих изменениях.

```cpp
bool right = true;
for (int i = 0; i < N; i++){
    // ... проверки ...
}
```
**Что происходит:** Заводим флаг `right` (по умолчанию `true` — считаем, что пирамида корректна). Пробегаемся циклом по всем элементам массива.

```cpp
    if (2*i + 1 < N && list[i] > list[2*i + 1]){
        right = false;
    }
    if (2*i + 2 < N && list[i] > list[2*i + 2]){
        right = false;
    }
```
**Главный нюанс (Маппинг индексов):** 
В задаче индексация с 1, а в С++ массивы индексируются с 0. Поэтому формулы пересчитываются:
* Левый ребенок в С++: `2*i + 1`
* Правый ребенок в С++: `2*i + 2`

**Условия в `if`:**
1. `2*i + 1 < N` — проверяем, что левый ребенок вообще существует (не вышли за границы массива).
2. `list[i] > list[2*i + 1]` — проверяем, что родитель **строго больше** левого ребенка. Если это так, то это **нарушает** инвариант min-кучи, поэтому ставим `right = false`.
То же самое для правого ребенка.

```cpp
if (right){
    std::cout << "YES" << std::endl;
} else {
    std::cout << "NO" << std::endl;
}
```
**Что происходит:** Выводим результат в зависимости от того, нашелся ли хоть один нарушитель.

## 3. Сложность алгоритма (Вопросы на защите)
* **Время работы (Time Complexity):** \(O(N)\). Мы проходим по массиву ровно один раз (один цикл `for`). Внутри константное количество операций.
* **Память (Space Complexity):** \(O(N)\). Мы используем вектор размера \(N\) для хранения входных данных.
* **Ограничения:** \(N \le 10^5\). Для \(10^5\) операций алгоритм со сложностью \(O(N)\) выполнится за доли секунды, что укладывается в любые лимиты времени (обычно 1-2 секунды).

## 4. Возможные вопросы преподавателя и ответы на них

**Вопрос:** Почему ты не используешь рекурсию для обхода дерева?
**Ответ:** Потому что пирамида (куча) уже хранится в виде массива. Связи родитель-потомок вычисляются математически через индексы. Простой цикл `for` эффективнее, не требует дополнительной памяти под стек вызовов и работает за \(O(N)\).

**Вопрос:** Что будет, если массив пустой или состоит из одного элемента?
**Ответ:** Если \(N=1\), цикл отработает один раз, условия `2*i+1 < N` не выполнятся, флаг останется `true`, программа выведет `YES`. Один элемент всегда является корректной пирамидой. Пустой массив по условию задачи невозможен (\(1 \le n \le 10^5\)).

**Вопрос:** Почему ты сравниваешь `list[i] > list[...]`? В задаче же написано `<=`?
**Ответ:** Задача просит проверить условие \(a_i \le a_{child}\). Если мы находим ситуацию, где \(a_i > a_{child}\) (родитель больше ребенка), это означает, что условие нарушено. Нам достаточно найти хотя бы одно такое нарушение, чтобы сказать `NO`.

**Вопрос:** Почему индексы `2*i + 1` и `2*i + 2`?
**Ответ:** В теории пирамид, если корень имеет индекс 0 (как в С++), то левый потомок находится по формуле \(2i+1\), а правый — \(2i+2\). В условии задачи индексация с 1, поэтому формулы выглядят как \(2i\) и \(2i+1\), но в коде мы адаптировали их под 0-индексацию.

**Вопрос:** Можно ли ускорить программу, не считывая весь массив?
**Ответ:** Технически можно считывать элементы и проверять их "на лету". Но для этого нужно хранить предыдущие значения, чтобы сравнивать ребенка с родителем. В текущем виде код максимально прозрачен и понятен. Память \(O(N)\) для \(10^5\) элементов ничтожна.

**Вопрос:** Почему в коде нет `break` после `right = false`?
**Ответ:** Это не ошибка, а особенность реализации. Даже если мы нашли нарушение, цикл продолжит работу до конца. Так как \(N \le 10^5\), это незначительно скажется на производительности. Однако, для идеального кода можно добавить `break`, чтобы не делать лишних проверок, как только найден первый баг.

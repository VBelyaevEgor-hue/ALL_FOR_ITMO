## Что делает программа

Программа:

1. Считывает четыре числа: `n`, `m`, `a`, `b`.
2. Генерирует массив `arr` из `n` чисел по формуле:
   - `cur = cur * a + b`
   - `arr[i] = (cur >> 8) % m`
3. Сортирует массив с помощью сортировки слиянием (`MergeSort`).
4. Во время сортировки подсчитывает количество **инверсий** — пар индексов `(i, j)`, таких что `i < j`, но `arr[i] > arr[j]`.
5. Выводит единственное число — количество инверсий.

Инверсии считаются «бесплатно» во время слияния: когда при слиянии двух отсортированных половин мы берём элемент из правой половины, это значит, что он меньше всех оставшихся элементов левой половины. Каждый такой оставшийся элемент образует с ним инверсию.

## Исходный код

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1'000'000;
uint32_t arr[MAXN];
uint64_t inversions = 0;
uint32_t cur = 0;

uint32_t nextRand24(uint32_t a, uint32_t b) {
    cur = cur * a + b;
    return cur >> 8;
}

void Merge(uint32_t arr[], int left, int mid, int right) {
    int i = 0;
    int j = 0;
    int result[right - left];

    while ((left + i < mid) && (mid + j < right)) {
        if (arr[left + i] <= arr[mid + j]){
            result[i + j] = arr[left + i];
            i++;
        } else {
            result[i + j] = arr[mid + j];
            inversions += mid - (left + i);
            j++;
        }
    }
    while (left + i < mid) {
        result[i + j] = arr[left + i];
        i++;
    }
    while (mid + j < right) {
        result[i + j] = arr[mid + j];
        j++;
    }
    for (int k = 0; k < i + j; k++) {
        arr[left + k] = result[k];
    }
}

void MergeSort(uint32_t arr[], int left, int right){
    if (left + 1 >= right){
        return;
    }
    int mid = left + (right - left) / 2;
    MergeSort(arr, left, mid);
    MergeSort(arr, mid, right);
    Merge(arr, left, mid, right);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    uint32_t n, m, a, b;
    if (!(cin >> n >> m >> a >> b)) {
        return 0;
    }

    if (n > MAXN) {
        cerr << "n exceeds limit\n";
        return 1;
    }

    for (uint32_t i = 0; i < n; ++i) {
        arr[i] = nextRand24(a, b) % m;
    }

    MergeSort(arr, 0, n);
    cout << inversions;
    return 0;
}
```

## Разбор `main`

```cpp
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    uint32_t n, m, a, b;
    if (!(cin >> n >> m >> a >> b)) {
        return 0;
    }

    if (n > MAXN) {
        cerr << "n exceeds limit\n";
        return 1;
    }

    for (uint32_t i = 0; i < n; ++i) {
        arr[i] = nextRand24(a, b) % m;
    }

    MergeSort(arr, 0, n);
    cout << inversions;
    return 0;
}
```

Что происходит:

- `ios::sync_with_stdio(false); cin.tie(nullptr);` — ускоряют ввод-вывод, отключая синхронизацию с C-потоками и привязку `cin` к `cout`. Это стандартный приём в спортивном программировании.
- Читаются четыре числа: `n`, `m`, `a`, `b`. Если ввод не удался, программа завершается.
- Проверка `n > MAXN` — защита от переполнения глобального массива `arr`, размер которого `MAXN = 1'000'000`.
- Цикл заполняет массив `arr` значениями, сгенерированными функцией `nextRand24(a, b) % m`.
- `MergeSort(arr, 0, n);` — запускает сортировку на полуинтервале `[0, n)`. Обратите внимание: правая граница не включается.
- Выводится глобальная переменная `inversions`, которая накапливается во время слияний.

### Почему массив глобальный?

`uint32_t arr[MAXN];` объявлен вне функций. Это важно, потому что массив на 1 000 000 элементов типа `uint32_t` занимает ~4 МБ. Если бы он был локальным в `main`, он лежал бы на стеке, который обычно ограничен 8 МБ (а с учётом других данных может не хватить). Глобальные переменные располагаются в сегменте данных, где места гораздо больше.

### Типы данных

- `uint32_t` — беззнаковое 32-битное целое (от 0 до 4 294 967 295).
- `uint64_t` — беззнаковое 64-битное целое. Используется для `inversions`, потому что максимальное число инверсий для `n = 1'000'000` равно `n*(n-1)/2 ≈ 5 * 10^11`, что не влезает в 32 бита (максимум ~4.29 * 10^9).

## Генератор `nextRand24`

```cpp
uint32_t nextRand24(uint32_t a, uint32_t b) {
    cur = cur * a + b;
    return cur >> 8;
}
```

Это линейный конгруэнтный генератор (LCG). Глобальная переменная `cur` изначально равна 0.

- `cur = cur * a + b;` — обновляет состояние.
- `return cur >> 8;` — возвращает старшие 24 бита (сдвиг вправо на 8 отбрасывает младшие 8 бит). Результат — число от 0 до 2^24 − 1 = 16 777 215.

Зачем сдвиг?  
Чтобы получить 24-битное число, которое затем по модулю `m` даст значение в диапазоне `[0, m-1]`. Это требование задачи (обычно `m` не больше 2^24).

Генератор детерминированный: при одних и тех же `a`, `b` и начальном `cur = 0` последовательность будет одинаковой.

## Функция `Merge`

```cpp
void Merge(uint32_t arr[], int left, int mid, int right) {
    int i = 0;
    int j = 0;
    int result[right - left];

    while ((left + i < mid) && (mid + j < right)) {
        if (arr[left + i] <= arr[mid + j]){
            result[i + j] = arr[left + i];
            i++;
        } else {
            result[i + j] = arr[mid + j];
            inversions += mid - (left + i);
            j++;
        }
    }
    while (left + i < mid) {
        result[i + j] = arr[left + i];
        i++;
    }
    while (mid + j < right) {
        result[i + j] = arr[mid + j];
        j++;
    }
    for (int k = 0; k < i + j; k++) {
        arr[left + k] = result[k];
    }
}
```

Функция сливает два отсортированных отрезка:

- левый: `[left, mid)`
- правый: `[mid, right)`

Используются индексы `i` и `j` — сколько элементов уже взято из левой и правой половин соответственно. Текущий элемент левой половины: `arr[left + i]`, правой: `arr[mid + j]`.

### Основной цикл слияния

```cpp
while ((left + i < mid) && (mid + j < right)) {
    if (arr[left + i] <= arr[mid + j]){
        result[i + j] = arr[left + i];
        i++;
    } else {
        result[i + j] = arr[mid + j];
        inversions += mid - (left + i);
        j++;
    }
}
```

Пока в обеих половинах есть элементы, сравниваем текущие. Если левый элемент `<=` правого, берём левый (это сохраняет устойчивость). Иначе берём правый и **добавляем к счётчику инверсий** количество оставшихся элементов в левой половине: `mid - (left + i)`. Почему? Потому что все эти элементы больше правого (так как левая половина отсортирована, и мы ещё не взяли ни одного из них, значит, они все >= текущего левого, а текущий левый > правого). Каждый из них образует инверсию с взятым правым элементом.

### Дописывание остатков

Если одна половина закончилась, просто копируем оставшиеся элементы другой половины. Инверсий здесь уже не возникает, потому что все оставшиеся элементы одной половины либо все больше, либо все меньше — но они уже не образуют новых инверсий с элементами другой половины, так как другая половина пуста.

### Копирование обратно

```cpp
for (int k = 0; k < i + j; k++) {
    arr[left + k] = result[k];
}
```

Результат слияния временно хранится в массиве `result` (VLA размера `right - left`), затем копируется обратно в `arr` на место `[left, right)`.

**Важно:** `int result[right - left];` — это VLA. В стандартном C++ так нельзя, но GCC/Clang разрешают. При больших `n` это может быть опасно для стека. В идеале нужно использовать `std::vector` или глобальный буфер.

## Функция `MergeSort`

```cpp
void MergeSort(uint32_t arr[], int left, int right){
    if (left + 1 >= right){
        return;
    }
    int mid = left + (right - left) / 2;
    MergeSort(arr, left, mid);
    MergeSort(arr, mid, right);
    Merge(arr, left, mid, right);
}
```

Классическая рекурсивная сортировка слиянием для полуинтервала `[left, right)`.

- База рекурсии: `left + 1 >= right` — если длина отрезка 0 или 1, сортировать нечего.
- `mid = left + (right - left) / 2` — находим середину (запись защищает от переполнения, но здесь `int` и `n` до 1e6, так что переполнение не грозит).
- Рекурсивно сортируем левую и правую половины.
- Сливаем их через `Merge`.

## Как считаются инверсии

Инверсия — это пара индексов `(i, j)`, такая что `i < j`, но `arr[i] > arr[j]`.

При слиянии двух отсортированных половин `[left, mid)` и `[mid, right)` мы сравниваем элементы. Если `arr[left + i] > arr[mid + j]`, то `arr[mid + j]` меньше не только `arr[left + i]`, но и всех элементов левой половины, начиная с `left + i` и до `mid - 1`. Количество таких элементов: `mid - (left + i)`. Каждый из них образует инверсию с `arr[mid + j]`. Поэтому мы добавляем это количество к `inversions`.

Так как сортировка слиянием рекурсивно разбивает массив на всё меньшие части, в итоге учитываются все возможные инверсии. При этом каждый элемент правой половины сравнивается с оставшимися элементами левой ровно один раз на каждом уровне слияния.

## Пример работы

Пусть `n = 4`, массив: `[3, 1, 4, 2]`.

Инверсии: `(3,1)`, `(3,2)`, `(4,2)` — всего 3.

### Шаг 1. `MergeSort(0, 4)`

`mid = 2`. Сортируем `[0,2)` и `[2,4)`.

#### Левая половина `[0,2)`: `[3, 1]`
- `MergeSort(0,1)` — ничего.
- `MergeSort(1,2)` — ничего.
- `Merge(0,1,2)`: сравниваем `3` и `1`. `3 > 1`, берём `1`, добавляем `mid - (left + i) = 1 - 0 = 1` инверсию. Результат: `[1, 3]`. `inversions = 1`.

#### Правая половина `[2,4)`: `[4, 2]`
- Аналогично: `Merge(2,3,4)`: `4 > 2`, берём `2`, добавляем `1` инверсию. Результат: `[2, 4]`. `inversions = 2`.

### Шаг 2. `Merge(0,2,4)`

Левая: `[1, 3]`, правая: `[2, 4]`.

- Сравниваем `1` и `2`: `1 <= 2`, берём `1`.
- Сравниваем `3` и `2`: `3 > 2`, берём `2`, добавляем `mid - (left + i) = 2 - 1 = 1` инверсию. `inversions = 3`.
- Сравниваем `3` и `4`: `3 <= 4`, берём `3`.
- Берём `4`.

Итог: `[1, 2, 3, 4]`, `inversions = 3`. Верно.

## Сложность и свойства алгоритма

### Временная сложность

Сортировка слиянием всегда делит массив пополам, глубина рекурсии `O(log n)`, на каждом уровне `O(n)` работы. Итого **O(n log n)** в лучшем, среднем и худшем случае. Подсчёт инверсий не увеличивает асимптотику.

### Память

- Глобальный массив `arr` — `O(n)`.
- Временный массив `result` в каждом `Merge` — в худшем случае `O(n)`. Так как рекурсия в глубину, одновременно активен только один `Merge`, поэтому дополнительная память `O(n)`.
- Стек рекурсии — `O(log n)`.

### Устойчивость

Сортировка слиянием **устойчивая**, потому что при равенстве (`arr[left + i] <= arr[mid + j]`) мы берём левый элемент. Это не влияет на подсчёт инверсий, но важно для сохранения порядка равных элементов.

### Тип данных для инверсий

`uint64_t` необходим, так как максимальное число инверсий для `n = 1'000'000` ≈ `5 * 10^11`, что больше `2^32 - 1 ≈ 4.29 * 10^9`.

## Вопросы на защите

### 1. Что такое инверсия?

Пара индексов `(i, j)`, таких что `i < j`, но `arr[i] > arr[j]`.

### 2. Как программа считает инверсии?

Во время слияния двух отсортированных половин. Когда берём элемент из правой половины, все оставшиеся элементы левой половины больше него, и каждый образует инверсию. Их количество равно `mid - (left + i)`.

### 3. Почему `inversions` имеет тип `uint64_t`?

Потому что максимальное число инверсий для `n = 1'000'000` — около `5 * 10^11`, что не влезает в 32-битное целое.

### 4. Зачем `ios::sync_with_stdio(false); cin.tie(nullptr);`?

Для ускорения ввода-вывода. Это отключает синхронизацию с C-потоками и отвязывает `cin` от `cout`, что ускоряет чтение больших объёмов данных.

### 5. Что делает `nextRand24`?

Это линейный конгруэнтный генератор. Он обновляет `cur = cur * a + b` и возвращает `cur >> 8` (старшие 24 бита). Затем в `main` берётся `% m`, чтобы получить число в диапазоне `[0, m-1]`.

### 6. Почему массив `arr` глобальный?

Чтобы избежать переполнения стека. 1 000 000 элементов `uint32_t` — это ~4 МБ, что может быть много для стека. Глобальные переменные хранятся в сегменте данных.

### 7. Что нестандартного в коде?

- `#include <bits/stdc++.h>` — не стандартный заголовок, но поддерживается GCC.
- `int result[right - left];` — VLA. В стандартном C++ размер массива должен быть константой времени компиляции. Лучше использовать `std::vector`.
- `using namespace std;` — не рекомендуется в больших проектах, но удобно в спортивном программировании.

### 8. Что если `n > MAXN`?

Программа выводит сообщение об ошибке в `cerr` и возвращает 1. Это защита от переполнения массива.

### 9. Почему `MergeSort(arr, 0, n)`, а не `n-1`?

Потому что используется полуинтервал `[left, right)`. Правая граница не включается, поэтому для сортировки всего массива из `n` элементов нужно передать `right = n`.

### 10. Как изменится код, если нужно считать не инверсии, а просто отсортировать массив?

Достаточно убрать строку `inversions += mid - (left + i);` и не выводить `inversions`.

«Программа генерирует массив из `n` псевдослучайных чисел с помощью линейного конгруэнтного генератора, затем сортирует его сортировкой слиянием и одновременно подсчитывает количество инверсий. Инверсии считаются при слиянии: когда элемент из правой половины меньше текущего элемента левой, все оставшиеся элементы левой половины образуют с ним инверсии. Их количество добавляется к глобальному счётчику. Временная сложность `O(n log n)`, дополнительная память `O(n)`. Используются типы `uint32_t` для элементов и `uint64_t` для счётчика инверсий. В коде есть нестандартные элементы: `bits/stdc++.h`, VLA в `Merge`, но они допустимы в GCC».

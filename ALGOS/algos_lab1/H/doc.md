## Что делает программа

Программа:

1. Считывает число `N`.
2. Считывает `N` пар чисел: `popularity` (популярность) и `stabilty` (устойчивость).
3. Каждой паре присваивает исходный номер `index` (нумерация с 1).
4. Сортирует все треки:
   - по `popularity` по убыванию;
   - при равной популярности — по `stabilty` по убыванию.
5. Проходит по отсортированному массиву и выбирает те треки, у которых `stabilty` строго больше, чем максимальная `stabilty` среди всех уже просмотренных (то есть среди треков с большей или равной популярностью).
6. Выводит количество выбранных треков и их исходные номера в порядке отбора.

Иначе говоря, программа находит **множество Парето-оптимальных** треков по двум критериям: популярности и устойчивости. Трек считается оптимальным, если не существует другого трека, который был бы не хуже его по обоим критериям и строго лучше хотя бы по одному.

## Исходный код

```cpp
#include <iostream>
#include <vector>

struct Track{
    int popularity;
    int stabilty;
    int index;
};

bool Compare(Track el1, Track el2){
    if (el1.popularity == el2.popularity){
        return (el1.stabilty >= el2.stabilty);
    } else {
        return(el1.popularity >= el2.popularity);
    }
}

void Merge(std::vector<Track>& list, int left, int mid, int right){
    int i = 0;
    int j =0;
    std::vector<Track> result(right - left);
    while ((left + i < mid) && (mid + j < right)){
        if (Compare(list[left + i], list[mid + j])){
            result[i+j] = list[left + i];
            i++;
        } else {
            result[i+j] = list[mid + j];
            j++;
        }
    }
    while (left + i < mid){
        result[i + j] = list[left + i];
        i++;
    }
    while (mid + j < right){
        result[i + j] = list[mid + j];
        j++;
    }
    for (int k = 0; k < i + j; k++){
        list[left + k] = result[k];
    }
}

void MergeSort(std::vector<Track>& list, int left, int right){
    if (left + 1 >= right){
        return;
    }
    int mid = left + (right - left) / 2;
    MergeSort(list, left , mid);
    MergeSort(list, mid, right);
    Merge(list, left, mid, right);
}

int main(){
    int N;
    std:: cin >> N;

    std::vector<Track> tracks(N);

    for (int i =0; i < N; i++){
        std::cin >> tracks[i].popularity >> tracks[i].stabilty;
        tracks[i].index = i+1;
    }

    MergeSort(tracks, 0, N);
    int max_y = -2000000000;    
    std::vector<int> answer;
    for (int i = 0; i < N; i++){
        if ( tracks[i].stabilty > max_y){
            answer.push_back(tracks[i].index);
            max_y = tracks[i].stabilty;
        }
    }

    std::cout << answer.size() << std::endl;
    for (int i =0; i < answer.size(); i++){
        std::cout << answer[i] << " ";
    }

    return 0;
}
```

## Разбор `main`

```cpp
int main(){
    int N;
    std:: cin >> N;

    std::vector<Track> tracks(N);

    for (int i =0; i < N; i++){
        std::cin >> tracks[i].popularity >> tracks[i].stabilty;
        tracks[i].index = i+1;
    }

    MergeSort(tracks, 0, N);
    int max_y = -2000000000;    
    std::vector<int> answer;
    for (int i = 0; i < N; i++){
        if ( tracks[i].stabilty > max_y){
            answer.push_back(tracks[i].index);
            max_y = tracks[i].stabilty;
        }
    }

    std::cout << answer.size() << std::endl;
    for (int i =0; i < answer.size(); i++){
        std::cout << answer[i] << " ";
    }

    return 0;
}
```

Что происходит:

- `std:: cin >> N;` — читаем количество треков. Запись `std:: cin` с пробелом допустима: пробелы между `::` и `cin` игнорируются.
- `std::vector<Track> tracks(N);` — создаём вектор из `N` структур `Track`. В отличие от VLA, это стандартный и безопасный способ.
- Цикл считывает для каждого трека `popularity` и `stabilty`, а также записывает исходный номер `i + 1` в поле `index`. Это нужно, чтобы после сортировки помнить, какой трек был каким.
- `MergeSort(tracks, 0, N);` — сортируем вектор на полуинтервале `[0, N)`. Правая граница не включается.
- `int max_y = -2000000000;` — инициализируем максимальную устойчивость очень маленьким числом. `-2 * 10^9` меньше любого возможного значения `stabilty` (обычно до 10^9), поэтому первый же трек точно пройдёт проверку.
- `std::vector<int> answer;` — сюда будем складывать исходные номера выбранных треков.
- Цикл `for (int i = 0; i < N; i++)` проходит по отсортированному массиву:
  - если `tracks[i].stabilty > max_y`, то текущий трек имеет устойчивость строго больше, чем все предыдущие (а значит, и все треки с большей или равной популярностью). Такой трек добавляется в ответ, а `max_y` обновляется.
- Выводится размер ответа и сами номера через пробел.

Почему `MergeSort(tracks, 0, N)`, а не `N - 1`?  
Потому что сортировка работает с полуинтервалом `[left, right)`. Для сортировки всего массива из `N` элементов нужно передать `left = 0`, `right = N`.

## Структура `Track`

```cpp
struct Track{
    int popularity;
    int stabilty;
    int index;
};
```

Структура хранит три целых числа:

- `popularity` — популярность трека;
- `stabilty` — устойчивость (в коде опечатка, должно быть `stability`);
- `index` — исходный номер трека (от 1 до `N`).

Структура используется вместо трёх отдельных массивов, что делает код удобнее: при сортировке все три поля перемещаются вместе.

## Функция `Compare`

```cpp
bool Compare(Track el1, Track el2){
    if (el1.popularity == el2.popularity){
        return (el1.stabilty >= el2.stabilty);
    } else {
        return(el1.popularity >= el2.popularity);
    }
}
```

Функция определяет порядок сортировки. Она возвращает `true`, если `el1` должен идти **не позже** `el2`.

Логика:

- Если популярности равны, сравниваем устойчивости:
  - возвращаем `true`, если `el1.stabilty >= el2.stabilty`, то есть трек с большей устойчивостью идёт раньше.
- Если популярности не равны, сравниваем популярности:
  - возвращаем `true`, если `el1.popularity >= el2.popularity`, то есть трек с большей популярностью идёт раньше.

Итог: сортировка по убыванию популярности, а при равной популярности — по убыванию устойчивости.

### Важный нюанс: почему `>=`, а не `>`

Обычно для строгого компаратора используют `<` или `>`, чтобы `Compare(x, x)` было `false`. Здесь при полном равенстве `Compare(x, x)` вернёт `true`. Для `std::sort` такой компаратор был бы некорректен (не задаёт строгий слабый порядок). Но в этой программе `Compare` используется только внутри собственной сортировки слиянием. Там это работает как правило:

> Если левый элемент `>=` правого, берём левый.

Это обеспечивает **устойчивость**: при равенстве первым выбирается элемент из левой половины, то есть тот, который стоял раньше в исходном массиве. Для данной задачи устойчивость не критична, но она не мешает.

## Функция `Merge`

```cpp
void Merge(std::vector<Track>& list, int left, int mid, int right){
    int i = 0;
    int j =0;
    std::vector<Track> result(right - left);
    while ((left + i < mid) && (mid + j < right)){
        if (Compare(list[left + i], list[mid + j])){
            result[i+j] = list[left + i];
            i++;
        } else {
            result[i+j] = list[mid + j];
            j++;
        }
    }
    while (left + i < mid){
        result[i + j] = list[left + i];
        i++;
    }
    while (mid + j < right){
        result[i + j] = list[mid + j];
        j++;
    }
    for (int k = 0; k < i + j; k++){
        list[left + k] = result[k];
    }
}
```

Функция сливает два отсортированных отрезка:

- левый: `[left, mid)`;
- правый: `[mid, right)`.

Используются индексы `i` и `j` — сколько элементов уже взято из левой и правой половин.

### Временный вектор `result`

```cpp
std::vector<Track> result(right - left);
```

Создаётся вектор размера `right - left`. В него складывается результат слияния. В отличие от VLA, это стандартный C++.

### Основной цикл слияния

```cpp
while ((left + i < mid) && (mid + j < right)){
    if (Compare(list[left + i], list[mid + j])){
        result[i+j] = list[left + i];
        i++;
    } else {
        result[i+j] = list[mid + j];
        j++;
    }
}
```

Пока в обеих половинах есть элементы, сравниваем текущие через `Compare`. Если `Compare(левый, правый) == true`, берём левый, иначе правый. Взятый элемент копируется в `result[i + j]`.

### Дописывание остатков

Если одна половина закончилась, просто копируем оставшиеся элементы другой половины. Они уже отсортированы.

### Копирование обратно

```cpp
for (int k = 0; k < i + j; k++){
    list[left + k] = result[k];
}
```

Результат слияния копируется обратно в исходный вектор `list` на место `[left, right)`.

## Функция `MergeSort`

```cpp
void MergeSort(std::vector<Track>& list, int left, int right){
    if (left + 1 >= right){
        return;
    }
    int mid = left + (right - left) / 2;
    MergeSort(list, left , mid);
    MergeSort(list, mid, right);
    Merge(list, left, mid, right);
}
```

Классическая рекурсивная сортировка слиянием для полуинтервала `[left, right)`.

- База рекурсии: `left + 1 >= right` — если длина отрезка 0 или 1, сортировать нечего.
- `mid = left + (right - left) / 2` — находим середину.
- Рекурсивно сортируем левую и правую половины.
- Сливаем их через `Merge`.

После вызова `MergeSort(tracks, 0, N)` весь вектор будет отсортирован по правилу, заданному в `Compare`.

## Как работает отбор ответа

После сортировки массив упорядочен так:

- сначала идут треки с наибольшей популярностью;
- среди них — с наибольшей устойчивостью;
- затем с меньшей популярностью и т.д.

Таким образом, когда мы проходим по массиву слева направо, все уже просмотренные треки имеют **популярность не меньше**, чем текущий.

Переменная `max_y` хранит максимальную устойчивость среди всех просмотренных треков.

Условие отбора:

```cpp
if (tracks[i].stabilty > max_y) {
    answer.push_back(tracks[i].index);
    max_y = tracks[i].stabilty;
}
```

Трек добавляется в ответ, если его устойчивость **строго больше**, чем у всех предыдущих. Это значит, что:

- по популярности он не превосходит предыдущие (они были не меньше);
- по устойчивости он превосходит все предыдущие.

Следовательно, не существует трека, который был бы не хуже его по обоим критериям и строго лучше хотя бы по одному. Такой трек является **Парето-оптимальным** (недоминируемым).

Важно: если два трека полностью равны по популярности и устойчивости, то после сортировки они стоят рядом, и только первый из них может быть выбран (второй не пройдёт условие `> max_y`, так как `max_y` уже равен их устойчивости). Это соответствует определению доминирования, где равные элементы не доминируют друг друга, но в данной реализации выбирается только один из них. Если в задаче требуется вывести все максимальные элементы, включая равные, это было бы ошибкой. Но часто в подобных задачах равные считаются одним и тем же, и достаточно вывести один.

## Пример работы

Пусть входные данные:

```text
4
3 1
3 5
2 4
1 10
```

Треки:

- №1: popularity=3, stabilty=1
- №2: popularity=3, stabilty=5
- №3: popularity=2, stabilty=4
- №4: popularity=1, stabilty=10

После сортировки по убыванию популярности, затем устойчивости:

1. №2: (3, 5)
2. №1: (3, 1)
3. №3: (2, 4)
4. №4: (1, 10)

Проход и отбор:

- `max_y = -2e9`
- i=0: №2, stabilty=5 > -2e9 → выбираем, `max_y = 5`, answer=[2]
- i=1: №1, stabilty=1 > 5? Нет.
- i=2: №3, stabilty=4 > 5? Нет.
- i=3: №4, stabilty=10 > 5? Да → выбираем, `max_y = 10`, answer=[2, 4]

Вывод:

```text
2
2 4 
```

Проверка: трек №2 (3,5) доминирует №1 (3,1) и №3 (2,4). Трек №4 (1,10) не доминируется никем, так как у него самая высокая устойчивость. Ответ: 2 трека, их номера 2 и 4.

## Сложность и свойства алгоритма

### Временная сложность

- Сортировка слиянием: `O(N log N)` в лучшем, среднем и худшем случае.
- Проход по массиву и отбор: `O(N)`.
- Итоговая сложность: **O(N log N)**.

### Память

- Вектор `tracks` — `O(N)`.
- Вспомогательный вектор `result` в каждом `Merge` — в худшем случае `O(N)`. Так как рекурсия в глубину, одновременно активен только один `Merge`, поэтому дополнительная память `O(N)`.
- Стек рекурсии — `O(log N)`.
- Вектор `answer` — до `O(N)`.

### Устойчивость

Сортировка слиянием **устойчивая**, потому что при равенстве (`Compare` возвращает `true`) берётся левый элемент. Это не влияет на отбор, но сохраняет исходный порядок равных элементов.

### Особенности

- `Compare` использует `>=`, что не является строгим компаратором. Для `std::sort` это было бы ошибкой, но для собственной реализации слияния работает корректно.
- Начальное значение `max_y = -2000000000` подобрано так, чтобы быть меньше любого возможного значения `stabilty`. Если устойчивость может быть меньше `-2e9`, первый трек может быть пропущен — это потенциальная ошибка.
- Название поля `stabilty` содержит опечатку (правильно `stability`), но на работу не влияет.

## Вопросы на защите

### 1. Что делает программа?

Находит и выводит номера треков, которые являются Парето-оптимальными по двум критериям: популярности и устойчивости. То есть таких, для которых нет другого трека с не меньшей популярностью и не меньшей устойчивостью, превосходящего хотя бы по одному параметру.

### 2. Что такое Парето-оптимальное множество?

Это набор элементов, каждый из которых не доминируется никаким другим. Элемент A доминирует B, если A не хуже B по всем критериям и строго лучше хотя бы по одному.

### 3. Зачем нужна структура `Track`?

Чтобы хранить три связанных значения: популярность, устойчивость и исходный номер. При сортировке все три поля перемещаются вместе, что упрощает код.

### 4. Как работает `Compare`?

Сравнивает два трека. Если популярности равны, сравнивает устойчивости по убыванию. Иначе сравнивает популярности по убыванию. Возвращает `true`, если первый трек должен идти раньше.

### 5. Почему в `Compare` используется `>=`, а не `>`?

Чтобы при равенстве левый элемент считался «не позже» правого. В собственной сортировке слиянием это обеспечивает устойчивость. Для `std::sort` такой компаратор был бы некорректен.

### 6. Как работает `MergeSort`?

Это рекурсивная сортировка слиянием. Она делит отрезок пополам, рекурсивно сортирует каждую половину, а затем сливает их в один отсортированный отрезок.

### 7. Что означают `left`, `mid`, `right`?

- `left` — начало отрезка (включается);
- `right` — конец отрезка (не включается);
- `mid` — середина, начало правой половины.

Левая половина: `[left, mid)`. Правая половина: `[mid, right)`.

### 8. Почему база рекурсии `left + 1 >= right`?

Потому что если длина отрезка `right - left` меньше или равна 1, то есть `left + 1 >= right`, сортировать нечего. Один элемент или пустой отрезок уже отсортированы.

### 9. Как работает `Merge`?

Он сливает две уже отсортированные половины. Идёт двумя указателями `i` и `j` по левой и правой половинам. Сравнивает текущие элементы через `Compare` и берёт тот, который должен идти раньше. Когда одна половина заканчивается, дописывает остатки другой. Результат складывает во временный вектор `result`, потом копирует обратно в `list`.

### 10. Как происходит отбор ответа?

После сортировки массив упорядочен по убыванию популярности, а при равенстве — по убыванию устойчивости. Проходим по массиву и храним `max_y` — максимальную устойчивость среди всех предыдущих треков. Если текущая устойчивость строго больше `max_y`, трек добавляется в ответ. Это значит, что он не доминируется ни одним из предыдущих (у которых популярность не меньше).

### 11. Почему `max_y` инициализируется значением `-2000000000`?

Чтобы быть меньше любого возможного значения `stabilty`. Обычно устойчивость лежит в диапазоне от `-10^9` до `10^9`, поэтому `-2 * 10^9` гарантированно меньше. Если бы устойчивость могла быть меньше `-2e9`, первый трек мог бы быть пропущен.

### 12. Что если два трека полностью равны?

После сортировки они стоят рядом. Первый из них будет выбран (если его устойчивость > `max_y`), второй — нет, так как `max_y` уже станет равным их устойчивости. В данной реализации выбирается только один из равных. Если по условию нужно вывести все максимальные элементы, это ошибка.

### 13. Какова сложность алгоритма?

`O(N log N)` по времени из-за сортировки слиянием. По памяти `O(N)` для вектора треков и вспомогательного вектора при слиянии.

### 14. В чём отличие от QuickSort?

QuickSort в среднем быстрее и сортирует на месте, но в худшем случае даёт `O(N^2)` и не устойчив. MergeSort всегда `O(N log N)`, устойчив, но требует `O(N)` дополнительной памяти.

### 15. Что нестандартного в коде?

- `std:: cin` с пробелом — допустимо, но необычно.
- Опечатка в названии поля `stabilty`.
- Компаратор с `>=` не является строгим слабым порядком, но работает в данной реализации.
- Начальное значение `max_y` может быть недостаточно маленьким в некоторых задачах.

## Краткое резюме

«Программа читает `N` треков, каждый с популярностью и устойчивостью. Запоминает исходный номер каждого трека. Сортирует треки по убыванию популярности, а при равной популярности — по убыванию устойчивости, используя сортировку слиянием. Затем проходит по отсортированному массиву и выбирает треки, у которых устойчивость строго больше максимальной устойчивости всех предыдущих. Это позволяет найти Парето-оптимальные треки: те, которые не доминируются никакими другими. Выводит количество выбранных треков и их исходные номера. Временная сложность `O(N log N)`, память `O(N)`. В коде используется собственная сортировка слиянием, структура `Track` и нестрогий компаратор `>=`, что обеспечивает устойчивость сортировки».
